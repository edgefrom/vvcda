## 0. 一分钟看懂我们做了什么

**一句话：这套系统是你的「副驾驶」，不是「自动驾驶」。**

- 它帮你把市场数据变成**看得懂的判断**（比如"降价能多卖多少"）；
- 它帮你**试算**每个方案的后果（比如"这样报产量会不会断现金"）；
- 但**方向盘始终在你手里**——最终决策由 4 个人讨论、人工提交。

```mermaid

    A[每回合结果 Excel] --> B[解析成结构化数据]
    B --> C[学会'份额怎么变']

    D --> E[给出建议+理由+风险]
    E --> F[你们讨论、人工提交]
    F --> A
```

## 1. 第一步：吃进数据

每回合结算后，平台会导出一份 Excel，里面有**所有公司**的定价、广告、渠道、研发、销量、份额、股价。

**这里有一个最关键的发现：对手的决策是完全可见的。** 我们能看到另外 9 家上一回合报了什么价、投了多少广告。这不是作弊——是平台本来就公开的数据，大家都看得到。

我们的系统第一步就是把这堆 Excel **自动解析**成整齐的表格，省去手工抄录。

---

## 2. 第二步：学会「市场份额怎么变」

这是整个系统的**心脏**。我们要回答一个核心问题：

> **「我动某个旋钮，市场份额会怎么变？」**

### 2.1 关键概念：相对量

我们不用「绝对价格」，而用「**相对价格**」——也就是**你的价格 ÷ 市场平均价格**。

为什么？因为顾客比的不是"399 贵不贵"，而是"**这家比别家贵多少**"。

- 你的价格 = 市场平均 → 相对价格 = 1.0 → 不占便宜不吃亏
- 你的价格 = 市场平均的 80% → 相对价格 = 0.8 → 占便宜
- 你的价格 = 市场平均的 120% → 相对价格 = 1.2 → 吃亏

广告、渠道同理：都用「相对平均水平」来衡量。

### 2.2 关键概念：S 曲线（logit）

份额和价格的关系不是直线，是一条 **S 形曲线**：

- 价格降一点点，份额涨一点；
- 降得越多，涨得越慢（边际递减）——因为你能抢的份额是有限的（最多 100%）。

我们用真实数据把这条 S 曲线的**形状**拟合出来。拟合结果就是一句话：

> **「相对价格每降低 10%，logit 份额大约增加 0.3」**（示例数字）

有了这条曲线，我们就能**预测**："如果我降到市场均价，我的份额会从 10% 涨到约 14.5%。"

### 2.3 一个真实算例（用我们赛区的样例数据）

我们拟合出的欧洲市场系数：

| 旋钮 | 系数 | 意思 |
|---|---|---|
| 相对价格 | **-3.1** | 价格高于平均 → 份额明显下降 |
| 相对广告 | +0.09 | 广告高于平均 → 份额小幅上升 |
| 相对渠道 | +0.04 | 渠道高于平均 → 份额微升 |

**立刻能读出的战略**：价格是主战场（-3.1 远大于广告的 +0.09），降价比投广告划算得多。

## 3. 第三步：让「数据很少」也能估准

我们只有 10 个回合 ≈ 160 个观测，这对统计学来说是**少得可怜**。普通方法很容易"瞎拟合"。我们用两个办法对抗：

### 3.1 贝叶斯先验：用市场调研当「先入为主的判断」

「先验」就是**在没看到数据之前，你已经相信的东西**。

市场调研报告已经告诉我们方向了：亚洲家庭用户对价格最敏感、高端企业用户最看重性能…… 我们把这些"已知的方向"作为**起点**，再用真实回合数据去**修正**。

> 打个比方：你估计一个陌生人的年龄，先按"大概 25 岁"（先验）猜，然后根据他的谈吐、长相（数据）逐步修正到 32 岁。如果没有任何先验，10 个样本根本猜不准。

### 3.2 置信区间：承认"估不准"

我们**不给出一个精确数字**，而是给一个**区间**：

> 相对价格系数 ≈ **-3.1，区间 [-5.9, -0.26]**

意思是：我们比较确定它是**负的**（降价有效），但具体是 -3 还是 -5 还不确定。**敢说"确定的部分"，也敢说"不确定的部分"**——这比硬报一个精确但可能错的数字更可靠。

### 3.3 在线更新：每回合自动刷新

系统用递归最小二乘（RLS），**每回合只吸收新数据，不用重跑全部历史**。所以每天结果一到，模型几分钟内就能更新到最新状态。

## 4. 第四步：算钱（财务仿真）

系统能模拟一整套**损益表**：

```
总收入 = 产品销售 + 维修收入
毛利润 = 总收入 - 可变成本
营业利润 = 毛利润 - 固定成本（管理/广告/渠道/研发/市场调研）
净利润 = 营业利润 - 税（亏损可结转抵扣）
```

还有几个比赛特有的规则，系统都考虑了：

- **亏损结转**：前几回合亏的钱，能抵减后面的税。
- **自动贷款**：现金不够时平台会自动贷款（所以别把现金卡到 0）。
- **销售预测误差**：你预测的销量和实际差越远，单位成本涨得越多——所以预测要认真填。

这套仿真用来回答："这个方案做完，我会不会断现金？会不会库存积压？"

---

## 5. 第五步：找方案（优化器）

系统会**自动搜索**一个"好的决策组合"，而不是穷举所有可能。

因为决策空间太大（6 个产品 × 每个产品的价格/特性/款式 × 两个市场 × 广告 × 渠道 × 研发），穷举到死也算不完。优化器用**进化算法**（模拟"优胜劣汰"）在合理时间内找到一个不错的方案。

它分两层：

1. **产品组合层**（离散）：选几个产品、投哪个市场；
2. **定价/营销层**（连续）：每个产品定多少钱、投多少广告。

最终输出的是**「建议值 + 一句话理由 + 置信度 + 备选方案 + 风险」**——让你们能快速看懂、快速否决。

## 6. 对手怎么对付

### 6.1 对手分类

系统会把 9 家对手粗略分成几类：
- **激进型**：爱降价、爱砸广告；
- **跟风型**：看别人动就跟着动；
- **稳健型**：变化不大。

### 6.2 情景对冲（而不是"预判对手"）

我们不猜"对手一定会怎么做"，而是问：

> **"如果对手集体降价 10%，我的方案还扛得住吗？"**

对几种可能的情景都试算一遍，选一个**在多数情景下都不亏**的方案。这叫**鲁棒**——不追求最好，追求"怎么都不差"。

### 6.3 纳什预判（防御性，默认不用）

「纳什均衡」是博弈论的概念：假设**所有对手都完全理性**，会收敛到的均衡价格。

我们实现了一个可插拔的纳什预判，但**默认不启用**。原因是：对手大多是学生队伍，不是理性机器，假设他们完全理性反而会误导我们。

它的唯一用途是**防御**：回答"如果对手极端理性且算得对，最坏情况他们能压价到多少？"——知道了这个下限，我们就知道自己的定价方案在最坏情景下还站不站得住。

## 7. 能帮你什么 / 不能帮你什么（诚实边界）

### ✅ 能帮你的

1. 把市场数据变成**看得懂的关系**（价格/广告/渠道对份额的影响大小）。
2. **试算**每个方案的财务后果，防止低级错误（断现金、库存爆、报错产量）。
3. 让练习回合的**实验更科学**（只动一个变量，最大化信息量）。
4. 每天几分钟内**刷新模型**、给出带理由的建议。

### ❌ 不能帮你的

1. **不能保证拿第一**——参数未知 + 9 个会学习的对手，没有标准答案。
2. **不能预测对手的每一步**——只能做情景对冲，不能未卜先知。
3. **不能自动提交**——也**不允许**，必须人工提交（赛事红线）。
4. **不会替你做商业判断**——它给的是"有依据的建议"，最终战略决策是人的责任。

> 记住：2025 年数据已经证明——顶尖队伍差距极小、前期波动拖后腿。
> **稳健、有依据、不犯低级错，本身就是赢面。** 这套系统的价值就是把这个"赢面"放大。

## 8. 术语表（中英对照）

| 中文 | 英文 | 一句话解释 |
|---|---|---|
| 相对价格 | relative price | 你的价格 ÷ 市场平均价格 |
| 市场份额 | market share | 你的销量占该细分总销量的比例 |
| 需求弹性 | elasticity | 价格/广告每变 1%，份额变几 % |
| 先验 | prior | 没看数据前就相信的判断（来自市场调研） |
| 置信区间 | confidence interval | 估计值的可信范围 |
| 在线更新 | online learning | 每回合增量刷新模型 |
| 亏损结转 | loss carryforward | 以前亏的钱可抵以后税 |
| 纳什均衡 | Nash equilibrium | 所有人理性时都不愿单方面改变的稳定状态 |
| 情景对冲 | scenario hedging | 对几种可能情况都做防御 |
| 优化器 | optimizer | 自动搜索好方案的程序 |
| 进化算法 | evolutionary algorithm | 模拟优胜劣汰的搜索方法 |
